# 统一证据规则：只命名观众实际看到的主体剧情

适用于今后全部素材，不限于1021试命名视频。主体剧情与片尾设定冲突时，直接排除片尾，不把冲突变成主体标签的待确认项。

## 检查流程

1. 确认主体剧情与营销结尾的边界，记录时间段。不能机械删除最后几秒：如果结尾仍在继续剧情，继续分析；若角色简介覆盖在剧情画面上，忽略简介层，仍读取底层剧情动作及对白。
2. 观察开头、中段、剧情结尾，发生镜头或字幕变化时补帧。读取开头钩子、剧情字幕、对话气泡，不能只看人物立绘或旧文件名。
3. 有语音对白时核对音轨：可用本地ASR辅助，与字幕交叉核验，保存时间戳。音乐、人声歌词、角色对白应区分；背景歌曲歌词不自动视为角色关系设定。无法听取或转写时明确说明，不能把字幕抄写包装成已识别语音；字幕足够时仍可据此给出有边界的结果。
4. 按主体剧情的核心情境判断一级分类，再判断关系、性格、职业、物种、POV、配对和视觉项。证据不足不强行填标签；职业未出现不加职业标签，用na维持固定字段。
5. 每项关键判断保留画面/字幕/对白依据。用户对当前剧情的明确解释可补充证据，但不能把某条素材的女性POV、mxf或职业设定扩展成所有素材的默认值。

## 完全排除

- 片尾角色简介、背景故事、推荐人物卡及用户未要求使用的外部角色档案。
- 片尾 Forbidden、Age gap、Alien 等预置设定标签。
- 品牌海报、Logo、下载页及多角色拼贴中的角色人数、发色、服饰、职业。
- 旧文件名中的剧情标签，只保留可核验的日期、渠道、人员、序号等元数据；TMM不进入本项目的新名称。

不得从排除内容补充缺失信息，也不得用它推翻主体剧情判断。

## 情境判定

- 开房/订房钩子、挑逗对白和身体吸引作为核心卖点时，优先考虑sr暧昧情欲，不因暖光、微笑、牵手而自动归纯爱。
- 暧昧不自动等于一夜情已经发生；刺激不自动等于暗黑恋爱或禁忌之恋。暗黑、禁忌仍需对应的危险、胁迫或制度性禁止证据。
- 剧情表现初次偶遇并发展浪漫吸引，或用户明确确认这一叙事方向时，可标ri陌生人变恋人；不是所有酒店场景都默认ri。角色不必在19秒内完成长期关系，但必须有陌生相遇及浪漫发展依据。
- 人数按主剧情角色计算，品牌结尾多男群像不将单男改成双男或多男。第一人称视角只露出的手不据此新增人物性别计数。
- 银白发、纹身、制服等依据主画面；角色简介声称的其他发色无效。职业未知不等于不存在，但无需为字段强行推断职业。
