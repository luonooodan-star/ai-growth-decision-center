# ROAS 与优化师行为报表

顶部导航“ROAS数据查看”进入 `/roas`；分析中心的“优化师 / 渠道行为漏斗”进入 `/analysis/behavior`。

两页选择 Mellow Android / iOS 和最多 31 天的日期范围后，点击查询。人员和渠道在已加载结果内筛选，可导出 CSV。查询期间保留原结果，不在页面加载或筛选切换时自动抓取。

ROAS 使用 `ads_paid_acquisition_daily.spend` 与相同产品、优化师、原始媒体渠道、安装日期的 `ads_paid_acquisition_cohort_metric.cumulative_metric_value` 对齐，收入筛选 revenue、D、0—14。缺失收入不补零，正消耗记录才展示。观察未完成标 *；累计收入回落标 ↓。媒体消耗时区检查 Asia/Shanghai；收入表时区未独立核实，页面提示。汇总 ROAS 按总收入 / 总消耗计算；任一记录缺失该日收入时不输出汇总百分比。

行为复用现有分析任务：按首开去重用户关联 D0 当日事件与订单。单角色聊天深度沿用现有 ≥5、≥20 口径。优化师通过 daily 表的 campaign_id 或精确 campaign_name 映射，冲突、缺失单列，禁止根据名称中的人员字符串猜测。逐用户 ID 留在服务端。报表缓存升级到 v3，避免把旧的无人员归属报表当作新报表使用。

新 ROAS 接口使用当前用户的 Doris 权限和个人缓存命名空间，不新增跨用户授权。行为报表沿用既有 Mellow 共享授权契约。设计只读角色仍受前后端页面/API 白名单限制。所有 Doris 请求复用现有完整性校验、受限并发和重复请求合并。

## 原参考页筛选契约

两个新页面共用相同筛选组件，顺序固定为产品、投放人员、渠道、安装日期范围、重置筛选。产品为所有产品 / Mellow 安卓 / Mellow iOS；人员为全部人员 / lzx / jsa / fjx。lzx、fjx 对应 FB / TT；jsa 对应 FB / Google Ads。渠道展示使用 FB、TT、Google Ads，来源别名统一映射供筛选。切换人员时保留合法渠道，否则回到全部渠道。

日期弹窗保留双月、周一开头、先起日后止日（逆选自动交换）、全部日期 / 最近 7 个数据日 / 最近 30 个数据日、取消 / 应用范围。默认和重置均选中当前可读取数据窗口的全部日期（从 2026-11-01 开始，最多最近 31 天，截止东八区昨日，遵循服务端单次范围限制）。产品、人员、渠道和日期均在已加载结果本地筛选，查询加载覆盖整个数据窗口的两个平台。手动加载按钮独立放置于筛选栏之外。

## 应用内行为日期对比与小时下探

行为页改为表格：每个产品 × 投放人员 × 渠道一张表；行为为行，日期为列组（最新日期最左），每组为去重用户数 / 占样本比例 / 事件次数。样本为当日 D0 首开去重用户，行为独立去重，不宣称严格顺序漏斗。查询所有事件名，已确认的埋点用中文显示，其余保留原埋点名，避免把未确认的首次设置或里程碑事件映射成其他指标；里程碑次数不从消息数量推算。

点击日期按需发起 behaviorDetail=true、hourly=true 的单日查询；原日表保留。小时表展示 00—23 时，每小时均以当天样本为分母，跨小时人数不可相加。使用参考查询已使用过的 event_timestamp 字段：仅接受秒 / 毫秒 epoch 或带明确时区的 ISO 时间；以 UTC+8 转换并核对 event_date，拒绝无时区时间和日期冲突。缺失时间或读取失败时明确报错，不生成零值小时图。新查询开关进入个人报表缓存 key，保留个人任务归属、受限并发、完整性校验与既有 Mellow 共享校验。逐用户事件只在服务端处理，前端仅收到聚合结果。

目前本地 Doris 连接返回 HTTP 502，代码、时区和去重逻辑可用模拟数据验证；公司环境的实际字段返回格式与完整性须待数据连接恢复后联调。
