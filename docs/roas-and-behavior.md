# ROAS 与优化师行为报表

顶部导航“ROAS数据查看”进入 `/roas`；分析中心的“优化师 / 渠道行为漏斗”进入 `/analysis/behavior`。

两页选择 Mellow Android / iOS 和最多 31 天的日期范围后，点击查询。人员和渠道在已加载结果内筛选，可导出 CSV。查询期间保留原结果，不在页面加载或筛选切换时自动抓取。

ROAS 使用 `ads_paid_acquisition_daily.spend` 与相同产品、优化师、原始媒体渠道、安装日期的 `ads_paid_acquisition_cohort_metric.cumulative_metric_value` 对齐，收入筛选 revenue、D、0—14。缺失收入不补零，正消耗记录才展示。观察未完成标 *；累计收入回落标 ↓。媒体消耗时区检查 Asia/Shanghai；收入表时区未独立核实，页面提示。汇总 ROAS 按总收入 / 总消耗计算；任一记录缺失该日收入时不输出汇总百分比。

行为复用现有分析任务：按首开去重用户关联 D0 当日事件与订单。单角色聊天深度沿用现有 ≥5、≥20 口径。优化师通过 daily 表的 campaign_id 或精确 campaign_name 映射，冲突、缺失单列，禁止根据名称中的人员字符串猜测。逐用户 ID 留在服务端。报表缓存升级到 v3，避免把旧的无人员归属报表当作新报表使用。

新 ROAS 接口使用当前用户的 Doris 权限和个人缓存命名空间，不新增跨用户授权。行为报表沿用既有 Mellow 共享授权契约。设计只读角色仍受前后端页面/API 白名单限制。所有 Doris 请求复用现有完整性校验、受限并发和重复请求合并。

## 原参考页筛选契约

两个新页面共用相同筛选组件，顺序固定为产品、投放人员、渠道、安装日期范围、重置筛选。产品为所有产品 / Mellow 安卓 / Mellow iOS；人员为全部人员 / lzx / jsa / fjx。lzx、fjx 对应 FB / TT；jsa 对应 FB / Google Ads。渠道展示使用 FB、TT、Google Ads，来源别名统一映射供筛选。切换人员时保留合法渠道，否则回到全部渠道。

日期弹窗保留双月、周一开头、先起日后止日（逆选自动交换）、全部日期 / 最近 7 个数据日 / 最近 30 个数据日、取消 / 应用范围。默认和重置均选中当前可读取数据窗口的全部日期（从 2026-11-01 开始，最多最近 31 天，截止东八区昨日，遵循服务端单次范围限制）。产品、人员、渠道和日期均在已加载结果本地筛选，查询仅加载当前选中的日期范围。手动加载按钮独立放置于筛选栏之外。

## 应用内行为日期对比与小时下探

行为页改为表格：每个产品 × 投放人员 × 渠道一张表；行为为行，日期为列组（最新日期最左），每组为去重用户数 / 占样本比例 / 事件次数。样本为当日 D0 首开去重用户，行为独立去重，不宣称严格顺序漏斗。仅查询关键行为白名单，表格固定为用户指定的 12 项，未确认埋点的首次设置/里程碑展示 —，不推算次数。

点击事件名（默认最新日期）或指定日期该事件的人数，按需发起 behaviorDetail=true、hourly=true、behaviorEvent 的单事件单日查询；原日表保留。小时表展示 00—23 时，每小时均以当天样本为分母，跨小时人数不可相加。使用参考查询已使用过的 event_timestamp 字段：仅接受秒 / 毫秒 epoch 或带明确时区的 ISO 时间；以 UTC+8 转换并核对 event_date，拒绝无时区时间和日期冲突。缺失时间或读取失败时明确报错，不生成零值小时图。新查询开关进入个人报表缓存 key，保留个人任务归属、受限并发、完整性校验与既有 Mellow 共享校验。逐用户事件只在服务端处理，前端仅收到聚合结果。

目前本地 Doris 连接返回 HTTP 502，代码、时区和去重逻辑可用模拟数据验证；公司环境的实际字段返回格式与完整性须待数据连接恢复后联调。

应用内行为页的数据窗口截止东八区今天，默认和重置均包含当天。今天列标为“回传中”，可继续按小时下探；未到的小时展示 —，不当作零事件。当天报表沿用每日快照缓存，用户点击重新抓取可主动更新。ROAS 页仍截止昨日。

## 两张报表的每日快照缓存

ROAS、应用内行为（含小时下探）使用独立持久化的“个人凭据版本 × 产品 × 日期 × 报表类型 × 小时模式”成功快照，不以 5 分钟 TTL 驱动反复查询。普通查询和筛选命中后只读取快照；新日期或首次查询缺失的切片才补齐。小时首次下探独立补齐该日。手动重新抓取可刷新；行为页既有 Mellow 共享用户可显式请求更新已授权的共享行为报表，仍通过 growth 固定产品范围和身份校验。

服务每分钟检查每日调度，东八区 10:00 开始串行更新已查询过的日期/产品切片，不自动追加未选中的今天或昨天。调度状态保存在 SQLite，服务重启不会重复刷新当天已尝试的任务；10:00 服务不在线时，恢复后补执行一次。失败保留成功缓存并记录提示，当日不自动重试，用户可手动重试。更新受前台空闲检查和现有后台单并发队列限制，前台 Doris 查询优先。10:00 是开始时间，完成时间取决于数据量和前台负载。

缓存使用既有 90 天持久存储清理规则；定时任务不回退到他人或系统凭据。旧的产品自动同步和广告观察任务不会主动重新生成这里的快照。

## 按当前选中日期抓取

查询数据和重新抓取均只发送当前选中的起止日期；按小时下探固定为所点单日。已有日期缓存继续读取，仅补齐该范围内缺失的日期。每日 10:00 调度只更新最近一次查询所选的日期/产品任务，不再自动追加今天或昨天；选新日期查询后会移除该报表旧选择的调度任务，成功缓存仍保留。后台刷新单日不会重置前台选择的整个任务范围。

## 超过 1,000 行的行为明细

分片器现在支持继续拆分查询中已有的 IN 用户 ID 数组，分组互斥，保留原日期、产品和其他筛选；不会因为 ID 已出现在 filters_json 就跳过它。每个查询过程最多两路请求，仍受全系统 Doris 并发门控、两分钟和 300 次请求预算约束。每个拆分节点及最终结果核对事件总数，异常不发布截断数据。行为对比仅需用户 × 事件计数，去掉 character_id；原素材分析保留角色维度以计算聊天深度。分小时模式继续保留 event_timestamp。

部署此修复后，对已保存失败状态的日期点击一次重新抓取即可重试，普通查询仍保留“每日更新 / 显式重试”的缓存策略。单用户单事件本身超过上限且没有可用分组时仍明确报错，不将截断结果视为完整数据。

## 关键行为白名单与单事件小时下探

所有行为明细必须携带 event_name 白名单：首次打开、首次设置、聊天页、发送成功、10/20/30 条消息里程碑、订阅展示、订阅点击、金币购买成功、发送失败和卸载。当前 10 项源埋点已确认，首次设置及 30 条里程碑尚待确认真实 event_name，空映射表示“待确认”，不请求、不显示 0、不用消息条数代替里程碑。

小时接口要求白名单中的单事件，拒绝任意事件、缺失事件、多日下探；仅抓取所点产品/日期/事件。为计算样本仍读取该日首开样本和归属，不拉取其他行为事件。小时成功快照及每日调度任务均按事件隔离；行为日缓存版本升级为 v2，旧全量日缓存可投影成关键事件缓存，保留原数据时间，不触发 Doris 查询；旧的无事件小时任务不再使用。ROAS 缓存和调度保持原版本。按白名单的别名映射先在单用户内合并，再统计去重人数，防止源别名造成重复用户。

历史核对来源：聊天 `01a1d297-0bb7-7541-b760-601ac74a239b`“分析 Mellow 安卓渠道漏斗变化”，11 月 13 日首轮分析明确列出 `message_10`、`message_20`。按当前需求展示 10/20/30 档，不再显示 5 条。30 条源事件以及首次设置没有在该记录中明确给出，实时 Doris 接口仍返回 502，因此保留未确认状态。
