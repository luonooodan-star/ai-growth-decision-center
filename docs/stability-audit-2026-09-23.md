# 效率与稳定性审查（2026-09-23）

本轮覆盖公司版启动/登录、Doris 手动与自动抓取链路、BI/广告调整缓存、Meta 桥接和提交锁、个人数据存储、页面轮询与表格计算、周复盘调度。属于代码审查和隔离回归测试，不是公司 Mac 全负载压测，也不证明此前偶发卡顿的唯一原因。没有删除历史数据、改变广告权限或执行真实广告修改。

## 已处理

1. **无界排队和多层队列**：移除 PaidGrowthService 的额外 FIFO，底层 DorisQueryGate 统一保留两个真实上游并发；队列最多 128 项、等待最多 60 秒。超时项删除且不会迟到执行，拒绝/异常释放槽位。排队超时不等于取消已经发送的上游请求。页面仍使用旧缓存/缺失标记，不把失败当成完整数据。
2. **多人争用**：底层出队优先选择与上一项不同的个人范围，减轻单一用户连续占队；不是严格公平或耗时保证。不会把不同个人的查询结果混合。
3. **重复查询**：相同个人数据范围、相同参数的在途 query_metric 合并；完成/失败即移除，不新增结果缓存。最多 128 个唯一在途查询。参数序列化顺序不同仍视为不同请求，以避免错误合并。
4. **定时遍历重入**：启动一分钟同步与每小时同步共用一份在途遍历；上一轮未完成不启动第二轮全用户遍历。原每用户抓取锁与观察调度防重入保留。
5. **401 混淆**：只有决策中心明确返回登录失效/身份变化才跳回登录页；Meta/Doris 的未授权错误不再被误作决策中心注销。
6. **轮询叠加**：产品决策和抓取记录的周期读取改为完成后延时再发，隐藏标签页暂停周期读取；手动操作仍可读取。不改变广告任务本身执行。

## 保留的边界

- Meta 展示读总并发 6、每凭据 2；广告提交每用户一任务、总量最多 4，同系列层级互斥，提交前实时校验不变。
- Doris 完整性、总分核对、1000 行截断检查、个人缓存隔离、90 天磁盘保留不变。
- 首次跨国/优化师细分数据仍需查询，不能把缺维度的旧汇总伪装为可筛选明细。
- 周复盘每 30 分钟检查、每小时产品同步、每 5 分钟扫描三小时观察到期任务仍保留；本次没有擅自关闭业务任务。

## 需后续测量/设计，未贸然修改

- SQLite 同步访问与大 JSON 解析运行在主线程，存在阻塞可能，但需事件循环延迟、返回行数和序列化耗时证据；不能根据健康接口以外的超时直接定性。
- 个人数据库连接最多 64 个；凭据版本变更会产生新范围。不可简单 LRU 关闭/重开：当前打开逻辑有“重启中断任务”恢复，必须先把任务生命周期与连接生命周期分离。
- 大表筛选仍在浏览器主线程汇总，账户页每批更新可能触发重复重算。后续可预聚合/虚拟滚动；必须保持选择、展开和草稿不丢失并做浏览器性能录制。
- 授权页身份检测、展示读取及提交预检成本不同；不可为了快而取消提交校验，亦不能把网络超时标成授权失效。
- 现有兼容入口、旧实验/观察记录仍有存量引用，不凭界面移除就直接删库/删服务。

## 部署后验证

两名不同授权用户同时查询，观察各自数据不串、排队是否收敛；隐藏/恢复标签页检查周期请求；在隔离环境模拟慢 Doris 与失败确认槽位恢复。公司现场仍应采集卡顿时健康响应和 CPU/内存，不能以本地 mock 测试宣称现场提速百分比。
