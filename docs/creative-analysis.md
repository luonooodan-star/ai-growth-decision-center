# 素材标签 × 用户漏斗

入口：顶部「分析中心」，路径 `/analysis`。这是独立的只读分析页；不会调用 Meta，也不会修改广告。

## 页面流程

1. 选择 Mellow 平台和首开日期（最多 31 天），点击「查询数据」。进入页面或修改条件不会查询 Doris。
2. 数据返回后，国家、平台、归因范围在本地切换。基础范围变化会清空标签路径。
3. 点击候选标签的「＋交叉」。所有已选标签是 AND 关系；下一层只展示仍有用户的共现标签。可点击路径回退或单独移除标签。候选标签各行不可相加。
4. 查看聊天/付费双漏斗、订单确认人数、国家/日期/素材明细。「较上层」为转化率百分点差，不是因果提升。
5. 「V2 提示词与命名检查」保留参考对话的原版 V2，可复制、查词典、检查文件名。不会自动调用模型生成标签；「复制 Codex 复盘材料」组合原提示词、选中路径与聚合证据，供人工发起分析。

V2 来源：ChatGPT 对话 `6ab224e1-f230-83ea-8d07-e54eec630aa1`「广告标签提示词完善」中用户提供的 V2。保留 8–10 个语义标签、`malefemale` 等原词表，不采纳后续未确认的修改建议。`dark`、`mys` 等复用代码保留多个可能维度，不从代码猜单一含义。无 V2 标记的旧命名不会被自动推断成 V2。

漏斗参考：Codex 对话 `01a084bb-3fd5-7d51-93db-490fd2360758`「对比买量用户行为差异」及本地 Mellow 09/25–09/27 报告的查询口径。历史报告不是当前页面数据；多标签交集重新从用户归因构建，不能拼接单标签聚合表。

## 数据合同

- 当前仅接入已核实的 Mellow Android（事件 app_id=12，bundle=com.pixelfly.mellow）和 iOS（事件 app_id=3，bundle=com.pixelflyapp.milo）。不将其他产品套用该合同。
- 首开：`bi_dwd.dwd_app_event`，`first_open`，按 app_id + resolved_user_id 去重；取所选范围内最早首开日。无有效 ID 的事件单列排除。这不是跨全历史去重的新注册定义。
- 聊天：首开同日 `chat_page_send_message_success`；5/20 深度按**同一 character_id**，不跨角色累计。缺少角色 ID 且无法确认阈值时显示缺失，不补零。
- 付费展示：`sub_show` 或 `purchase_page_view`；点击：`sub_click` 或 `pur_click`；成功：`sub_success` 或 `pur_succ`。嵌套用户交集，不声称已验证事件的时间顺序。另展示独立的任意成功埋点人数。
- 归因：`xy_online_data.tbl_user_access_permissions_all`，bundle_id + user_id。iOS 回看首开前 89 天（含首开日为 90 天），Android 保留原有 7 天回看；均允许首开后 1 天回传，且不超过今天。查询仍限制为当前批次用户 ID，不扫描返回全量历史用户。Android 保留 `adgroup` 素材名、`creative` 素材 ID 的原合同；iOS 额外限定 platform=2，从 `creative` 的“文件名（数字广告 ID）”拆出名称和 ID，不把广告组名称或设备 `ad_id` 当作素材。完整性检查使用可加总的 `user_count`。多个不同归因仍单列冲突，不任取其一。
- Meta 来源包含已核实的 iOS Web 别名 `xiye_Milo_ios_web_pruchase`；保留原始渠道名，不把未知 Web 来源一概归为 Meta。
- 订单：双平台均读取 `xy_online_data.tbl_user_order`，bundle_id + user_id + 首开日，`PURCHASED` / `Production`；iOS 必须 platform=2。使用 `order_count` 检查完整性，最终按用户去重，不累计重复订单人数。独立于成功埋点；读取失败为 null，不补零。仅计首开人群 D0 订单，不代表当天全部付费用户。
- 覆盖状态分别显示：可解析 V2、有素材但无 V2、无素材归因、只有素材 ID、有 V2 标记但无法解析、归因冲突、读取失败。旧素材仍参与无标签条件下的行为/订单统计，不硬生成标签。
- 日期按 Doris `event_date` 对齐，不把业务表 app_id 与事件 app_id 直接等同。

## 权限、缓存与负载

- 默认沿用当前用户的个人 Doris Key 和源端权限。无权访问事件/归因/订单表时显示失败/缺失，不使用管理员凭据回退。仅下述明确授权的 fjx、jsa 走定向共享。
- 任务、原始读取缓存和聚合报告按用户名 + 凭据版本隔离；更换 Key 不复用旧空间。浏览器只接收互斥聚合行，不返回用户 ID。
- 手动启动任务，同一用户同口径请求合并；每人最多 1 个、全进程最多 2 个活跃分析。分片沿用受限并发与完整性校验，拒绝截断结果。
- 任务每个阶段检查八分钟上限；已发出的单次读取需结束后才能停止。前端轮询只读任务状态，不重新查询 Doris。取消后不再发起后续读取；离开页面仅停止浏览器轮询，后台任务受上述上限约束。
- 首开读取最多 50,000 行；行为与归因按 200 用户分批。同一日期/平台的一项来源读取失败后，后续批次不重复轰炸该来源。缺失来源不补零，部分报告不进入完整报告缓存。
- 已结束日期缓存有效期 24 小时；含当天的报告 5 分钟。仅「重新抓取」显式绕过有效缓存。读取存储沿用项目 90 天清理；有效期不是保留期限。
- iOS 修复使用 schemaVersion=2 和 creative-funnel:v2 缓存空间，旧映射缓存不会被复用。

## 验证边界

单元测试覆盖 V2 原词表、精确标签匹配、逐层交集、用户去重、同角色深度、D0/平台/订单隔离、缺失值、冲突归因、个人任务隔离、并发/取消和部分数据缓存限制。公司 Doris 在线验证仍须使用拥有上述表权限的个人账号完成；该代码不扩大源端权限。

## growth → fjx / jsa 定向共享

- 授权名单在服务端 `mellow-sharing.ts` 固定为 fjx、jsa；只共享 Mellow iOS、Android 的现有分析中心聚合报告（包含自然量），以及 Mellow iOS 含自然量 D0 ROAS。其他账号、其他产品、通用投放数据与 Meta 广告权限均不改变。
- 部署后两人登录「分析中心」，查询数据会按指定日期/平台读取 growth 缓存；缺失或过期才以 growth 的本机加密凭据按固定合同同步。浏览器不会得到 growth Key，也不能自定义数据集、数据所有者或任意查询。共享读取不需要两人另配高权限 Key。
- 共享者最多查询最近 90 天中的 31 天；不能强制绕过有效缓存。今日缓存 5 分钟、历史 24 小时，保留期沿用 90 天清理。没有增加后台定时全量抓取；两人同口径请求复用源任务。停止等待不取消其他人的任务。任务句柄按查看者隔离，growth 更换/撤销 Key 后旧句柄失效。
- 页面单独提供「读取 / 同步 iOS ROAS」。固定 app_id=3，分母为 `ads_paid_acquisition_daily.spend` 的全渠道之和；分子为 `ads_paid_acquisition_cohort_metric` 中 `metric_id=revenue, cohort_index=0, cohort_unit=D` 的全渠道之和，包含 organic 与 Web。ROAS 为总收入 / 总消耗，不平均各渠道比率。此安装 cohort 口径独立于事件表的首开漏斗口径，不受下方标签/国家筛选影响。
- 空数据、来源失败、产品不符不补零；零消耗不计算 ROAS。显示查询日期和源数据时间。无权访问共享接口时直接拒绝，而不是将同一共享例外扩展到通用 BI 或广告写入接口。
- 公司 Mac 仍需部署构建、重启决策中心并保留 growth 已配置的个人 Doris Key；首次由 growth / fjx / jsa 在上述入口手动查询完成同步。不需要给 fjx、jsa 复制 Key，不需要重新安装 Meta 桥。
