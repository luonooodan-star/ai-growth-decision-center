# 多人并发（单公司 Mac 服务进程）

- HTTP 登录改用异步 scrypt，最多同时两个密码推导任务，相同验证请求合并。成功验证短缓存 30 秒、最多 256 项，仅保存进程随机 HMAC 指纹。每请求重新检查用户配置，停用/密码变化立即阻止旧缓存复用；失败不缓存，在途上限 128。配置异常按未授权处理。
- 展示用 Meta GET 总并发最多 6，同一凭据指纹最多 2；调度跳过已经占满个人额度的请求，让其他用户使用空闲槽位。只读缓存及在途合并仍按凭据隔离。身份检测、预检和写入不以展示缓存代替实时校验。
- 同时最多 4 个独立调整任务。锁粒度为 `accountId:campaignId`，跨个人数据分区保护整条系列层级；同一系列的系列/广告组/广告修改互斥。每用户仍只允许一个正在执行的任务，每任务内按原顺序执行。冲突返回明确提示，需要完成后重新预检，不自动重试或偷偷排队执行。
- 留档失败时保留进程锁，不继续写入；需人工核对后重启恢复。任务成功结束或正常报告失败时释放锁。
- Doris 查询仍保留既有四路上限、个人缓存隔离和完整性校验，不盲目增加数据库负载。
- 必须使用单个决策中心服务进程。当前锁为进程内锁，不支持多个副本/cluster；扩容多进程前必须改为跨进程的持久化锁。

本次需要重建决策中心、重新安装原工具适配器并重启两侧服务。以上为代码并发上限，不是公司网络下的吞吐或耗时承诺；需部署后用多人账号实测 Meta 限流和网络情况。

## 本地筛选与登录切换

- 首次抓取三个日期的系列 × 优化师 × 国家汇总（仅本人 Doris 权限范围），不预取所有素材；切换广告账户、优化师、国家、搜索条件只做本地 AND 筛选并重算指标。展开系列仍按需加载该系列的层级数据，三天缓存及完整性校验保留。首次升级此查询粒度会产生新缓存，不能伪用缺少维度的旧汇总。
- `/login` 提供用户名/密码登录。右上角“切换账户”和“退出登录”撤销当前会话，返回登录页；其他标签页同步刷新。草稿按用户名及 Doris 配置版本隔离，不跨人载入。
- 会话为随机 HttpOnly / SameSite=Strict cookie，最长 8 小时；服务重启、用户配置变更都会要求重新登录。HTTPS 下额外设置 Secure；现有 HTTP 内网入口并不加密传输，应仅在可信内网使用，长期建议配置可信 HTTPS。
- 浏览器不再使用历史 Basic 登录缓存。明确的非浏览器 Basic API 客户端仍兼容。Cookie 写请求要求同源及页面会话绑定，旧标签页不能在新身份下继续提交。
- 切换账户不会撤销个人 Meta / Doris 授权，也不会取消已经提交执行的广告任务。
