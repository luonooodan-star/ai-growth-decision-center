# Doris 完整抓取与续抓

## 工作方式

- 保持只读 query_metric，不使用不存在的 offset/cursor，也不通过提高 limit 绕开接口限制。
- 所有 query_metric 请求限制最多 1000 行，同时最多 2 个在途查询（含诊断查询）。
- cohort、投放明细、广告明细按数据日读取。到达上限、返回截断标记或声明行数超过实际返回行数时，枚举系列清单。
- 系列清单达到上限时按源数据返回的国家拆分发现 ID，合并去重；真正查询仍沿用原国家范围，避免将国家级 ROAS 简单相加。
- 系列按最多 100 个一批读取；分片仍超限则二分系列列表，再按接口支持的广告组/广告 ID 细分。
- 最小清单或最小分片仍超限则明确报缺口，需要 Doris MCP 提供稳定分页，不会伪装完整。

## 完整性与保护

- 每个数据日查询前后核对同口径汇总，检查消耗/展示合计；D0 cohort 固定 revenue / D / index=0，分别核对 cohort_spend 和 cumulative_metric_value，再以收入合计除以消耗合计核对 ROAS。无消耗分组也可能有收入，不能仅用 ROAS 加权反推收入。
- 合计校验遵循 SQL SUM 的 NULL 语义，排除显式 NULL；原明细保留 NULL，不改为 0。字段缺失、非法数字、实际合计不一致仍拦截。有消耗却缺少 ROAS 也不通过校验。
- 重复行去重，相同维度的冲突数据拒绝发布；跨分片筛选范围或日期的行拒绝发布。
- 数据源在抓取过程中改变汇总时不发布该日；这不是数据库一致性快照，仍不能替代上游提供的快照游标。
- 任一必需来源失败时，该数据日不发布新的系列或产品快照，旧指标和原抓取时间保留，并标记暂不可用于新判断。其他已完成日期可继续发布。
- 无数据、返回字段缺失与接口失败不作为 0 处理。cohort 未成熟仍不等于回报为 0。
- 可选版位/年龄等接口不支持时保留既有降级提示，不据此声称已经获得这些维度。

## 续抓与缓存

- 校验合格的分片保存在本地 SQLite 的 growth_fetch_checkpoint；键包含产品、查询条件及本日源汇总指纹。
- “补齐缺失数据”和定时任务可以复用 2 小时内、源汇总指纹未变的分片；汇总仍会重新查询校验。
- “补最近 7/14/30 天”和“立即抓取”主动重新查询，不复用分片。
- 重启将遗留运行中任务标为部分完成，可继续补齐；不会伪造上一次运行成功。
- 内部分片缓存 48 小时后清理；“清空历史”也清理缓存。历史正式快照不受缓存清理影响。
- 同一产品重复点击复用当前运行；其他产品正在抓取时明确提示等待。
- 每轮查询预算有限，网络瞬断最多重试 2 次；鉴权错误、字段错误不做无意义的网络重试。

## 页面与部署

- 抓取历史展示请求日期范围、当前步骤、复用分片数量、缺口日期及数据源。
- “补齐缺失数据”续抓；需要全量复核可选择“补最近 N 天”。操作完成展示真实运行结果，不固定显示补齐成功。
- 沿用公司 Mac update.sh；数据库新表自动建立，无需妙搭授权、额外模型或新的 Doris 写权限。
- 必须在公司环境升级后点击补齐验证真实源数据；本地模拟测试不能证明公司 Doris 权限或数据源可用性。
