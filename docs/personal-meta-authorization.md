# 公司 Mac 个人登录与 Meta 授权

决策中心沿用浏览器 Basic 登录，保留环境变量配置的 `growth` 账号。新增个人账号只存放在 Git 忽略的 `runtime/center-users.json`，权限 0600、随机盐及 scrypt 哈希，不保存明文密码。每个用户必须配置本人的 Doris Key；应用独立保存每人的数据，实际可查询的数据范围由 Doris 服务端权限决定，不能用一个全量 Key 代替行级授权。

## 部署与创建用户

在公司 Mac 决策中心仓库拉取代码后执行：

```sh
npm run build:company
node scripts/company-mac/add-center-user.mjs fjx
node scripts/company-mac/setup-meta-local-bridge.mjs /Users/toufanga/Downloads/work/meta-asset-uploader
launchctl kickstart -k "gui/$(id -u)/com.meta-creative-vault"
launchctl kickstart -k "gui/$(id -u)/com.luonooodan.ai-growth-decision-center"
```

创建命令交互输入密码，不回显，不覆盖现有用户。不要将密码或 runtime 文件提交到 Git。公司 Mac 必须运行创建命令；开发机的 runtime 不会随 Git 同步。Basic 登录应使用受信 HTTPS；现有 HTTP 入口只应在受控内网使用，不得公开到公网。

## 同事验证

1. 使用独立浏览器配置或无痕窗口打开决策中心，以 `fjx` 和约定密码登录。浏览器可能记住原有 Basic 登录，不要共享浏览器配置。
2. 顶部应显示当前用户名 `fjx`。
3. 点击决策中心右上角“桥接”状态按钮进入 `/authorization`。在同一浏览器的原上传工具里登录本人的 Meta，再点击“打开 Meta 授权 / 撤销页面”。
4. 授权页面应显示 `fjx`，确认后只保存该用户的会话；切勿使用别人已登录的 Meta 会话授权。
5. 返回决策中心“授权与连接”，在 Doris 卡片点击“配置我的 Doris Key”，填写自己的 Key；保存后页面刷新，再查询本人数据。产品目录、指标标准和已审核 Skill 从原共享库读取，无需每人重新建立；广告账户、抓取快照不继承旧共享数据。Meta 状态通过只读身份检测后才显示“已授权”，连接失败显示“连接异常”；Doris 的“已配置”只表示保存，不冒充连接验证。
6. 检查账户、读取状态及预算。实际修改需要单独预检和确认。

签名授权链接有效期 5 分钟，一次使用；只接受由已登录决策中心生成的用户名。仅在本机受鉴权桥中透传个人身份，不能由浏览器自报用户名选用他人会话。授权文件为 `.users`，不读取旧 `.session` 的共用授权，旧文件保留但不再使用。每个用户（包括 growth）均需重新绑定；撤销只影响本人。会话保存状态不是 Meta 实时权限验证，真正权限由原 API 预检验证。

旧桥不带个人协议版本头时，决策中心拒绝执行，避免只升级一侧而回退到共用授权。原 Meta key、OAuth 和上传逻辑保持不变。

任务同时记录决策中心用户名及 Meta 用户 ID，同一 Meta 身份绑定到多个中心用户也不能互相提交任务。旧无用户名任务保留审计，但不作为任何新用户的可提交任务。浏览器草稿使用用户名独立键，旧共用草稿不会自动迁移。个人抓取快照、账户归属、操作任务仍独立；产品目录、指标规则、已审核知识和 Skill 周报告共享。各优化师的周报告按用户区分，避免同周同产品相互覆盖。

## Doris 权限与历史数据

广告调整页的账户归属不再查询缺少 `buyer_alias` 的 Doris DWD 表：先用本人的 Doris Key 获取可见系列 ID，再通过当前中心用户名对应的 Meta 桥接会话读取 `account_id`。按 10 个系列分批，每批最多 2 个只读请求；不持久缓存授权结果。无权读取的系列不生成归属映射，仍禁用操作；混合身份响应整批作废。账户映射成功只表示可读，实际操作权限仍由预检和提交时原 API 校验。此修改须重新运行桥接安装脚本并重启原上传工具；不能只更新决策中心前端。

- Key 以 AES-256-GCM 加密保存于 `runtime/personal`，主密钥及凭据文件仅公司 Mac 系统用户可读（0600）；不要提交 Git，备份应同时保护主密钥。该机制防止配置明文泄漏，不防拥有主机管理员权限的人。
- 未配置时，不读取服务器环境变量或 Keychain 的共用 Doris Key。配置接口只接收 Key，不接受客户端指定用户名。
- 数据空间、查询合并、抓取任务按用户名及凭据版本隔离。更换/撤销 Key 将切换空间，不再访问旧权限缓存；旧库留档，不删除，也不会把旧全量历史自动迁入个人空间。更换 Key 后重新同步本人数据即可，团队标准和 Skill 不受影响。
- 每小时自动同步使用各有效账号自己的 Key；周复盘从本人的操作和快照取证，报告汇入团队 Skill。普通广告分析任务的执行账号仍必须与任务所属账号一致。

授权页使用 `Referrer-Policy: same-origin`，避免 `no-referrer` 使同站表单的 Origin 变成 null。仍拒绝 null 或跨站 Origin，并验证签名一次性票据、Host 和表单 nonce；不通过放宽来源校验解决授权报错。
- “已保存凭据”不代表 Key 有效或行级权限正确。上线验收需要数据管理员配置受限 Key，至少用两个不同范围的账号实测返回范围、导出和系列详情。若不同 Key 都拥有全量读取权限，本应用不能猜测其人员/职能归属，也不会把前端优化师筛选冒充权限。
- 源端收紧同一个 Key 的权限时，本系统无法自动获知历史数据的授权范围变化。管理员必须同时在本系统撤销/更新个人 Key（或禁用账号），以切换数据空间并阻止访问旧历史；不能仅修改源端权限或前端筛选项就认为历史数据已清除。
