# 公司 Mac 本机广告桥（无需给决策中心配置证书）

决策中心继续使用 HTTP 8081；原广告工具继续使用已有 HTTPS 3001。没有新增 8443、CA、证书、Meta key 或 OAuth 应用。浏览器无需共享两个入口的 Cookie。

## 一次安装

在公司 Mac 更新到包含本功能的版本后执行：

```sh
cd /Users/toufanga/Services/ai-growth-decision-center
npm run build:company
node scripts/company-mac/setup-meta-local-bridge.mjs /Users/toufanga/Downloads/work/meta-asset-uploader
```

安装器自动安装调整 API、增加 Vite 本机桥插件、备份修改前的 `vite.config.ts`，将独立桥凭据存入 Git 忽略的 `runtime/meta-local-bridge.json`（0600）。不读取、显示、复制或轮换 Meta key。不自动重启服务或修改广告。

**运行方式限制：**本机桥挂在原工具的 `vinext dev` / Vite 服务进程中，已用原工具临时副本联调验证。`npm run build` 本身不会启动它，`vinext start` 也不会执行该插件。公司若通过 launchd 管理，必须确认原服务使用 `npm run dev`；不要同时启动第二个占用 3001 的进程。现有服务不是这种模式时先检查启动命令，不盲目改动生产进程。

按原服务管理方式重启原广告工具、决策中心。随后：

1. 在原广告工具正常登录 Meta。
2. 打开 `https://192.168.3.173:3001/growth-center-link`，阅读授权范围，点击“授权当前登录给决策中心”。
3. 回到 `http://192.168.3.173:8081/adjustments`，读取配置、预检、核对清单后才能执行修改。

原广告工具本身仍须能正常、安全登录。本方案不修复它已有的证书主机名不匹配，不应跳过浏览器安全警告；它仅避免决策中心也配置 HTTPS，以及跨端口共享 Cookie。若原工具登录本身被浏览器证书阻止，需要先解决其入口问题。

## 安全与留档

- 内部桥只监听 `127.0.0.1:18761`，同时校验连接来源、Host、独立随机凭据、方法和固定路径，拒绝浏览器跨站调用。决策中心禁用环境代理、禁止重定向，只允许这个回环地址。失败不回退到匿名/公开模式。
- 原加密会话在用户主动授权后存入同目录 `.session` 文件（0600），最多 7 天；不解密或复制 Meta key。真实身份和权限仍由原 API 核验。过期或 Meta 登录失效需重新授权。
- 本机授权是**共享操作身份**：持有决策中心访问密码的优化师可使用该 Meta 身份。现有日志记录授权 Meta ID 与修改前后值，不应声称可以区分共用密码的每个人。需要实名审计时应另加独立用户登录。
- 可在授权页撤销。退出原工具浏览器登录不等于撤销本机授权；撤销停止后续请求，已经发送给 Meta 的请求无法撤回。
- 原上传 API、Graph 客户端、key、加密算法、原上传队列保持不变。本机桥将请求交给原 API，仍要求二次确认、原值冲突检查、修改后回读、失败停止，不自动重试有歧义的修改。
- HTTP 8081 不加密密码和操作内容，仅适用于受控局域网，不能暴露公网或不可信网络。

## 回滚

先在授权页撤销本机授权。恢复安装器生成的原 `vite.config.ts.*.bak` 并重启原工具；将决策中心 `runtime/meta-local-bridge.json` 移到受保护备份位置后重启决策中心。保留操作记录，不删除数据库、不更换原 key。此前 HTTPS 模式若未配置，回滚后广告修改会明确不可用。

## 验证

- 单元测试覆盖配置的回环限制、文件权限。
- `node --test test/meta-local-bridge.test.mjs` 使用临时本机模拟服务验证鉴权、明确授权、撤销和请求转交。
- 授权页兼容 HTTP/1.1 `Host` 和 HTTP/2 `:authority`；两者冲突时拒绝，不能使用 `X-Forwarded-Host` 绕过校验。回归测试覆盖真实本机 HTTP/2 请求、错误地址、跨站 POST。
- 原工具临时副本的 Vite/Workers 联调已验证：模拟加密会话由本机桥送达实际适配 API，并被原 `getMetaToken` 拒绝为 401；未使用真实会话、未调用 Meta、未修改真实广告。生产 Meta 登录和实际权限需安装后验收。
